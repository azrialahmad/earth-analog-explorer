# Terrain scoring parity fixtures

`frontend/public/data/test-fixtures/terrain-scoring.json` is a **test-only** artifact for cross-language regression tests. It contains synthetic parameter values, not observed target/site measurements, production scores, or new defaults. The app does not load this file for ranking.

## Generate and check

From the repository root:

```sh
uv run pipeline/scoring_fixtures.py
uv run pipeline/scoring_fixtures.py --check
uv run pipeline/scoring_fixtures.py --selftest
```

The generator reads ranges and default weights from `config/weights.yaml`, then calls `similarity` and `terrain_match` in `pipeline/scan.py` for the expected per-parameter similarities and aggregate terrain match. It records SHA-256 fingerprints for that scorer, the generator, and the config. No timestamps, raw raster data, new dependencies, or downloaded inputs are involved. Running the generator twice with unchanged files produces byte-identical JSON.

## Fixture contents and use

Cases cover identical values; each configured parameter at and beyond its configured range; partial/all missing inputs; unequal, zero, and all-zero weights; non-finite inputs encoded as JSON-safe markers; ties and null-score ordering; the configured windows; and Moon/Mars body labels. Each site's expected record includes per-parameter similarity, weighted sum, included/total weight, completeness, missing keys, and the aggregate score. Values and expected results are generated by code, not transcribed manually.

The `window_km` field labels a synthetic set of already-computed descriptors for a consumer test. The Python scanner currently scores its configured main window; the fixture generator does not compute terrain windows. The target body is metadata: the terrain formula itself is body-agnostic.

For rank-order checks the artifact uses the frontend contract—score descending, null last, and site ID ascending for ties. The scan's greedy candidate selection has a different tie-break (latitude then longitude); its retrieval ordering is not being changed. A TypeScript consumer should decode `{ "non_finite": "NaN" }`, `{ "non_finite": "Infinity" }`, and `{ "non_finite": "-Infinity" }` to the corresponding non-finite numeric inputs before invoking its similarity helper; these markers keep the JSON standards-compliant.

This artifact is intended for #65 to test the browser engine against Python-generated outputs. A passing fixture self-test proves only that generation is deterministic and cases exercise the declared Python path; browser parity is established only when the frontend test consumes these cases.
